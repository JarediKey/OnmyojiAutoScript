# Windows 空闲部署

[English](safe-update.md)

`deploy/safe_update.py` 准备已发布的 `origin/prod`，仅在所有存活工作进程确认处于
安全的调度等待阶段时切换源码。它不会仅根据界面的 RUNNING 状态或日志推测就
终止运行中的任务。此部署程序不使用 AI 或 API 凭据。

## 准入与切换

工作进程执行任务、空闲收尾、关游戏、启动模拟器时始终持有系统文件锁，只有
`Script.wait_until` 会释放。空闲确认包含 PID、配置摘要和下次唤醒时刻。部署程序
非阻塞地取得所有账号锁，拒绝过期进程、配置变更及三分钟内将唤醒的情况，并在
切换期间持有锁。启动准入锁防止新进程进入游戏操作。任何进程忙碌都会立即推迟
更新，不会终止它的任务。

部署窗口为北京时间 08:10（含）至 08:50（不含）。`--wait` 在窗口内每 30 秒重试
忙碌检查。GitHub 完成过晚、主机不可用或没有空闲机会时，等待下一次调用。
不会通过关闭任务或改动调度时间来挤出维护窗口。

下载和完整离线回归在取得空闲确认之前于隔离工作树中完成，当前账号模型仅在
内存中校验。未发布的已跟踪修改、分叉历史、运行环境依赖变更，以及已跟踪的
私有／部署配置变更都会阻止自动部署，要求先审查，不执行强制重置。测试日志
与私有配置快照保留在主机备份目录。

确认空闲后，程序备份配置，仅停止经过身份核验的 OAS 后台进程树，快进更新源码，
确认配置哈希未变，再在登录用户的桌面会话中以 `--run-none` 启动后台。健康检查
成功后才通过现有 WebSocket API 启动此前存活的账号进程，不擅自启动原本停止或
崩溃的配置。源码切换超时为 15 秒，后台健康检查限时 20 秒，账号并行启动限时
20 秒。下载／测试均不占用这段空闲后台切换时间。

在账号启动之前，如果源码切换或后台健康检查失败，程序核对受管启动器记录的
确切 PID，退回原版本并恢复此前工作进程。新账号进程已经启动后发生问题，只
报告失败，不自动回滚以免中断其任务。

## 主机配置

在 OAS 仓库根目录使用自带 Windows Python：

```powershell
.\toolkit\python.exe deploy\safe_update.py --settings D:\Onmyoji\automation\deploy.json --wait
```

私有设置 JSON 包含 `root`、`backup_root`、`port`、`launcher_task`、
`backend_pidfile` 和 `test_pythonpath`。测试路径指向单独安装的测试依赖，生产
启动器不得继承该路径。启动器是当前登录用户的手动 Windows 计划任务，以隐藏
窗口从 `root` 执行 `toolkit\python.exe server.py --run-none`，将子进程 PID 写入
`backend_pidfile`。MuMu IPC 需要桌面会话，不能从 SSH 会话 0 启动游戏后台。

`GET /maintenance/status` 仅向本机回环连接报告实际存活的工作进程与后台 PID，
拒绝远程连接。`--run-none` 启动参数明确覆盖命令行和部署配置中的启动名单。

第一次安装需要独立确认空闲后重启一次，让进程加载文件锁协议。旧工作进程没有
空闲确认能力，会被自动部署拒绝；程序没有针对旧版本的强制停止兜底。初始化时
须保留私有配置和获准的本地源码补丁。

`--prepare-only` 可以在窗口外验证候选，不切换进程／源码。程序用 JSON 报告
`up_to_date`、`prepared`、`deferred`、`deployed` 或 `failed`。应查看报告，而非
只看退出码：推迟是正常成功结果，并不代表版本已经部署。
