# 战斗等待选项

[English](README.md)

战斗等待使用源头的类型化运行状态：`battle_wait_strategy` 选择处理函数，
`battle_wait_options` 提供各事件的选项数据类。选项依次叠加类型默认值、装饰器
覆盖值、当前上下文覆盖值。覆盖以整个事件选项对象为单位；未填写字段使用其默认值，
包括奖励点击排除区域。嵌套上下文退出后恢复外层状态。装饰器调用结束或抛出异常时
恢复调用前的选项，避免临时设置泄漏到后续任务。原 `with_options()` 接口由
`with battle_wait_options(...)` 替代。

处理函数接收共享 `pub` 和各自的 `pri` 状态。任务所有者切换时重置任务状态，
每次通过装饰器调用战斗时重置单场状态。完成阶段只有在 `pub.per_battle.success`
为 `BattleResult.SUCCESS` 时返回 `True`；完成不等于胜利。失败处理先记录
`BattleResult.FAILURE`，再开启完成阶段。

## 战后统计入口排除

共用战后随机点击始终排除两处统计入口：领奖页左上角 `(44,32,72,72)`，以及
胜利页下方 `(383,559,52,49)`。矩形格式为 `(x,y,宽,高)`，原点在左上角。
第二处复用已有的 `C_END_SOUL_DETAILS` 区域。

排除规则覆盖胜利后的第一下随机点击、后续领奖点击和完成阶段兜底点击；即使
任务传入空列表或自定义排除列表也保留。不改变对已识别胜利标识的第一次点击。

回归检查：`python -m pytest tests/tasks/Component/GeneralBattle`。
这些是离线检查，不代表游戏实测。

## 旧通用战斗准备确认

`run_general_battle()` 完成预设／加成设置后等待两秒，再最多进行三次重新截图的
准备确认，每次间隔两秒。未锁定阵容时点击已识别的“准备”；锁定阵容保留自动
准备，只观察状态。确认真正进入战斗后立即结束重试。第三次确认及其等待结束后，
才开始独立的五秒确认超时计时；切换预设耗时不占用该确认时间。

必须确认实际进入战斗，才能开始等待赛果。已识别的胜负／奖励页也算有效进入，
允许短战斗在等待期间直接结束；准备页不算进入战斗。无法确认进入或赛果时抛出
`GameStuckError`，使用原有恢复流程，不再空等五分钟。本修改作用于共用的旧
`GeneralBattle.run_general_battle()` 流程，独立的类型化战斗处理框架保持原样。

离线检查：`python -m pytest tests/test_battle_prepare_confirmation.py`。
实际等待效果仍需模拟器验证。
