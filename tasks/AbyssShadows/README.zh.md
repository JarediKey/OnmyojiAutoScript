# 狭间暗域

[English](README.md)

本任务支持区域／敌人顺序、独立御魂预装、锁定阵容，以及自然结束／计时／伤害
目标策略，复用共享导航和账号全局皮肤设置。发布代码不会自动更新生产目录或
私有账号配置。

## 首轮测试配置

可移植的任务配置片段见 [abyss-trial.json](../../deploy/examples/abyss-trial.json)。
请使用独立的代码与配置目录，不要将它放进仍使用旧模型的生产后端。

- 给四个号分别准备独立测试配置，仅在生产主机本地复制对应设备及全局设置，
  每份只启用狭间任务，测试后端及四个实例全部保持未启动。
  测试后端使用独立端口 22289，关闭自动更新和依赖安装。启动测试前，先停止
  对应的生产任务；同一个模拟器不能同时由两个脚本控制。
- 周五／六／日手动进入活动、开始录屏，再启动测试。测试不自动开启活动或选择难度。
- `attack_order: A` 只测试神龙。旧版区域缩写展开为精英4/5/6、副将2/3、首领1。
  可填写 `A-1;A-2;A-3;A-4;A-5;A-6` 明确改变顺序。A/B/C/D 对应神龙／孔雀／
  白藏主／黑豹。分隔符为英文分号，不是 `>`。
- 三类策略均为 `FALSE`：等待自然结算，不按设定秒数主动退场。预设留空，
  关闭换御魂和标记，请手动准备当前队伍，不从其他任务猜用预设。
- `lock_team_enable: true` 跳过所有战前换阵容，包括不同敌人类型之间的切换。
  它不操作游戏里的锁定／解锁按钮，请先在游戏内设好锁定队伍。御魂预装独立执行。
- 正常完成后返回庭院并安排下次运行，不强制请求人工接管来停止实例。保护性
  异常仍会停止等待检查；监督测试完成后，请按需要手动停止测试实例。

## 生产部署

备份生产代码和私有配置，并停止对应实例及后端后，再更新代码目录。保留每个
生产账号的设备设置、最新全局皮肤、调度和其他任务，不要把整份旧测试配置覆盖
到生产。按当前模型／示例设置 `process_manage` 和 `abyss_shadows_time`，移除过时
的测试选项，并在重启前检查界面参数结构。发布 `prod` 不等于授权启动服务或开启
任何账号任务。

## 四账号设置

[abyss-trial-accounts.json](../../deploy/examples/abyss-trial-accounts.json) 是脱敏的
**process_manage 配置补丁**，不是可直接运行的完整账号配置。只能在隔离测试实例
停止时合并对应任务小节，保留设备、全局设置、调度和进度；不得用它覆盖整份私有
配置。准备好这些补丁不代表已经部署到生产主机。

| 账号 | 主攻目标 | 兜底目标 | 所有敌人类型的预设 |
|---|---|---|---|
| 1／2 | A 全部，再 B 全部 | D 首领、C 首领、D 两个副将、C 两个副将、D 三个精英、C 三个精英 | 7,2／7,1 |
| 3／4 | C 全部，再 D 全部 | B 首领、A 首领、B 两个副将、A 两个副将、B 三个精英、A 三个精英 | 6,1／2,1 |

主攻区域内仍为精英→副将→首领。兜底使用现有 `A-1` 显式目标语法，不新增解析器，
也不是自动跨账号协同。四份补丁均开启锁定阵容和御魂预装、关闭标记，战斗策略
均为 `FALSE`。相同御魂预设每次任务启动只预装一次，不按区域或场次重复预装；
锁定阵容不会关闭御魂预装。

## 页面切换与延迟

- 前三档难度菜单分别使用独立搜索区域：易 `(620,380,90,64)`、普
  `(620,450,90,64)`、难 `(620,520,90,64)`，排除下拉菜单底部的当前难度显示。
  模板与阈值保持不变，尚不支持“极”。提供的录像中“难”带锁，因此尚未实测
  解锁后的“难”选择流程。菜单展开／收起的小范围 UI 裁图随测试保存，不包含
  账号昵称、聊天或完整截图。
- 复用账号全局 `costume_config`：任务初始化时由 `CostumeBase` 替换战斗和式神录
  模板。不新增狭间专用皮肤选项或重复素材；离线测试也应用相同映射。
- 仅在式神录专属标记可见时返回。式神录消失，且狭间导航与式神录入口
  同时可见后停止。单独出现黄色返回不允许再点；过渡状态只等待，30秒仍无法
  确认则请求人工接管。
- 挑战入口允许直接进入战斗，不强制经过准备页。准备按钮／预设面板优先于
  退出图标；使用全局皮肤适配后的战斗信息标记确认战斗。准备按钮可点击时
  按间隔重试，变暗或预设面板未关时不点。单独出现退出图标不算开战。
- 未启用锁定时按需选择预设，随后重新截图确认，再处理准备。启用锁定时完全
  跳过战前选预设。无论开关如何，已经开战都不会被打断来切换阵容。
- 本任务显式的点击／滑动重试间隔翻倍，包括它调用的共享组件：0.6→1.2秒、
  1→2秒、2→4秒。共享组件源码、截图频率、战斗时限、动作时长、固定等待和
  调度间隔不变；没有指定重试间隔的调用保持原语义。
- 记录开战、退出式神录的状态变化。入口、式神录退出、战斗或战斗退出的保护性
  超时会在 `log/error/abyss/` 保存诊断帧；这些图片属于私有资料，不公开原始截图。

## 行为与限制

`TRUE` 表示立即退场，1～3位数字表示秒数，4位及以上数字表示伤害门槛（含边界）。
`FALSE` 等待自然结算。这是旧重构的策略语义，不是未来讨论的无限清区域模式。
每个目标仍最多两次尝试。寻路失败、尝试耗尽记录到 `saved_params.failed`，
不计入 `done`，也不计入可选的2/4/6补足配额。未确认胜利就返回地图不算胜利。

战斗等待上限300秒，超时请求人工接管，不主动认输；退出确认上限30秒。
异常时恢复截图频率。准备界面、进攻阶段无法确认时也停止等待人工检查。
保留上游“从神社直接返回活动地图”的入口修复。

没有“晚于计划时间两小时就跳过”的限制。任务通过调度配置
安排下次运行；上游原本独立的周五／六／日时间字段不属于这套模型。
原 `general_battle_config`、`switch_soul_config` 被 `process_manage` 替代，
不会自动将上游旧设置转换为新配置。

进度按自然日区分。正常完成且没有失败目标时清空；否则保留进度并使用失败调度。
收尾时以结束时间加成功／失败间隔计算下一次运行。共享调度器中，`server_update=09:00`
表示不强制钟点，其他值则使用 `server_update`／`delay_date` 覆盖间隔计算结果，
`float_time` 添加随机延迟。区域进入失败以任务开始时间加失败间隔计算，不套用
强制钟点。非周五／六／日不会进入活动，按成功调度安排下次运行。
只有明确需要从头重测时才在停止状态清空 `saved_params`。写入进度前会重载配置，
以保留其他已保存字段；仍不支持一边运行一边编辑配置。

录像帧检查覆盖四个账号的式神录／地图／准备／战斗识别，包括不同界面皮肤。
这是离线证据，不代表恢复后的正常调度收尾已实机验证。区域封印 OCR 和单敌人死亡判断仍需
单独验证。本次没有加入可靠的单敌人死亡识别、
无限重试或自动四号分组协同。多套御魂以确定顺序预加载，共用式神仍可能互相覆盖
  御魂；确认队伍安排前请保持测试中的换御魂关闭。

录屏覆盖进入活动前到返回庭院后。录像、原始配置和日志在本地保存。
人工接管前先停止测试实例，单独关闭 GUI 不一定停止后端点击。
测试结束后关闭测试后端，再恢复该模拟器的生产实例。

## 验证

```sh
python -m unittest discover -s tests -p 'test_*.py' -v
```

检查覆盖真实 OCR 像素过滤和模拟的狭间控制流程，不消耗活动机会。设置
`ABYSS_RECORDING_FRAMES` 指向提取帧目录可额外执行44帧私有录像回归；未设置则
跳过。原始帧／录像不随仓库分发或上传。修改源 JSON／图片后，通过 `dev_tools.assets_extract` 的
`AssetsExtractor('tasks/AbyssShadows').extract()` 重新生成 `assets.py`。
